<what-to-do>

Interview me briefly about the essential goals and main features of this website using plain, non-technical language.

Focus on 3 to 5 broad questions covering:
1. Site purpose and main goal
2. Primary visitor action (e.g., filling out a form, booking, buying)
3. Key content sections needed

Translate my non-technical responses directly into a concise technical plan and glossary.

For each question, suggest a sensible default or common web pattern.

Ask the questions one at a time, waiting for feedback before moving on.

</what-to-do>

<supporting-info>

## Domain awareness

Look for `CONTEXT.md` in the root folder and create it if missing once the first main feature is defined.

## During the session

### Rapid plain-English translation

Keep discussions high-level and focused on visitor outcomes. Translate plain-English requirements into technical terms without asking the user to explain technical mechanisms.

### Update CONTEXT.md inline

Instantly document key terminology and primary site features in `CONTEXT.md` as soon as they are agreed upon.

### Offer ADRs for key tools

Only suggest an ADR for major non-technical trade-offs (e.g., choosing third-party forms vs. hosted landing page services).

</supporting-info>
